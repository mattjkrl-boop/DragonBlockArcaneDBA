# Katana After Audit (Phase 1 template weapon, Nov 1, 2026)

Design lock: concepts/media-generation-dba-katana-concept-0-591a0e9b-5976-43ea-a4a1-8059714d4c53.webp (silver-white curved blade, pale energy edge, round silver tsuba, black diamond wrap with white showing through, silver pommel).

What changed, all generated by tools/build_katana.py (rerunnable):
- geckolib/models/item/katana.geo.json rebuilt: was 1 bone, 65 extruded-sprite cubes, 64x64. Now 5 bones (weapon root, grip, guard, blade, blade_glow), 18 true 3D cubes, 128x128 atlas. Grip is a white rayskin core with black wrap bands and a silver-dark pommel; guard is a crossed-box tsuba plus habaki collar; blade is 4 tapering segments with a gentle curve and an angled tip; blade_glow is a separate edge strip bone riding the cutting edge.
- textures/item/katana_geo.png (new, the geo atlas) and katana_geo_glowmask.png (new, transparent except the edge region and a faint tsuba ring). The flat katana.png sprite and its glowmask are untouched, so the GUI, ground, and frame look is unchanged.
- geckolib/animations/item/katana.animation.json (new, per-weapon): idle sway with a glow breathing pulse, a wider swing with a glow flash, and a charge loop with a raised tilt, micro shake, blade vibration, and a pulsing glow edge. Shared dba_weapon animations no longer apply to katana (see the MIGRATED set in DbaGeoWeaponRenderers).
- renders/katana_geo_preview.png: side view rendered from the actual cubes and atlas.

Display standard check (Phase 1 list):
- Holding and using, first and third person: per-context scale and offset from DbaWeaponRenderer, separate animation timelines per context from the perspective-aware foundation, per-holder state from the foundation tickets.
- Other players: holder-driven swing and charge via tickets, per-stack ids, trails already iterate all players.
- GUI, ground, fixed: unchanged flat sprite path. Head, on_shelf, offhand: geo fallback with the new model; offhand use now drives the charge state through the same tickets (the old hook checked main hand only).

Verification (audit, not a compile):
- Both JSON files parse; bone, cube, and atlas dimensions verified by script.
- No Java changed in this commit, so the foundation javac pass still stands.
- Preview is an orthographic side projection from the generator; it ignores cube rotation (tip) and draws enclosing wrap bands under the core, so the handle reads whiter in the preview than the model data specifies. The wrap bands fully enclose the core in their Y bands in the geo data itself.
- Residual flags: the glow layer texture is derived from the model texture resource by the same convention the other 19 weapons already use in game (path plus _glowmask), now applied to the katana_geo atlas; first in-game screenshot should confirm the edge glow and the FP and TP framing, and DbaWeaponRenderer holds the tuning values if they need adjustment.
